# ADR-0178 插件专属扩展点与可信扩展图

- 状态：已采纳
- 日期：2026-07-31

## 背景

系统已有内核公共扩展点、Backend Capability Registry、Portal 页面和语义 Slot，但“一个主要功能插件允许其他插件扩展自身”仍只能借公共菜单或直接调用实现。直接导入主插件源码、传递 React 节点或为每个主插件增加专用回调，会形成编译耦合、权限借用、版本漂移和热替换旁路。

用户中心是首个明确场景：其他插件需要增加安全、会话或通知页面，但不能修改头像、Shell、个人中心源码，也不能因为挂载到个人中心就取得个人中心权限。

## 决策

1. Manifest 增加两个通用、语言无关字段：主插件用 `extensionPoints` 声明自己拥有的扩展点，扩展插件用 `extensions` 声明贡献。扩展点 ID 必须位于所有者插件命名空间，贡献 ID 必须位于贡献者插件命名空间。
2. 扩展点包含 surface、精确契约版本、kind、dispatch、可选治理目标和闭合 JSON descriptor Schema。贡献包含目标扩展点、surface、契约范围、稳定 ID、顺序和 JSON-only descriptor。
3. 扩展插件必须在 `dependencies` 中显式依赖扩展点所有者。可信装配边界统一检查所有者是否存在、插件版本范围、扩展契约范围、descriptor Schema、single 基数和目标所有权；任何不一致都拒绝整个候选，而不是静默丢弃贡献。
4. 插件源码之间不得直接导入。descriptor 不携带组件、函数、DOM、凭证或语言对象；运行实现仍由贡献者自己的签名模块提供，并保留贡献者自己的权限、配置、状态和故障边界。
5. Portal Catalog 从已验签 Manifest 生成不可变 `ExtensionGraph`，与模块图写入同一个 RuntimeSpec 和 Generation。Node Host 与 Browser Kernel 使用同一个 `@vastplan/plugin-extension-contract` 解析器；浏览器不接收原始 Manifest 或 descriptor Schema。
6. 每个插件只得到宿主裁剪的 `PluginExtensionAccess`：所有者可枚举自身扩展点的全部贡献，贡献者只能看到自己的绑定，其他插件不可观察。插件不能在浏览器运行时伪造、增删或替换扩展图。
7. 第一种受治理 kind 为 `frontend.page`。扩展点所有者声明受治理导航目标；贡献 descriptor 锁定 `pageId + groupId`。Portal 在注册结束后反向核对页面所有者、页面 ID 和导航分组，并拒绝未声明关系却挂载到受治理目标的页面。
8. 扩展图随 Generation 原子切换。候选扩展不兼容、目标页面缺失或贡献者注册不一致时，候选 Generation 失败，活动 Generation 不受影响。卸载贡献者会随旧 Generation 一并移除页面和扩展视图。
9. Backend、Desktop 和 Mobile 后续复用相同 Manifest 模型。Backend 执行仍通过现有 Protocol Bus/Capability Registry，不把进程内对象或通用“任意调用”接口引入扩展协议。

## 备选方案

- **只使用内核公共扩展点**：简单，但无法表达主插件专属契约、所有权和版本，保留为不需要主插件语义的普通贡献方式。
- **主插件导出注册函数或共享源码 SDK**：初期快，但破坏独立发布、热替换和多语言边界，否决。
- **每个主插件设计专用宿主 API**：会复制装配、版本、权限和卸载机制，否决。

## 影响

- 主插件现在可以拥有稳定、版本化、可发现的扩展面，而不进入内核硬编码。
- 发布链增加扩展图校验，但浏览器稳态不解析仓库或 Manifest；运行期开销只是一份按 Generation 冻结的小型索引。
- 新增扩展点属于主插件公共契约变更，应提升主插件 SemVer，并同步示例、Profile 精确引用、测试和文档。
- `cn.vastplan.foundation.frontend.identity.account-center@0.2.0` 首先发布 `cn.vastplan.foundation.frontend.identity.account-center.page@1.0.0`。
