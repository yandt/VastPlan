# ADR-0198 激活门禁活跃性与引导协调器重试

- 状态：已接受
- 日期：2026-08-08
- 关联：[ADR-0197 平台控制 Profile 存在性作为 Provider 必需的真相源](ADR-0197-平台控制Profile存在性作为必需真相源.md)、[平台控制数据库 Bootstrap](../architecture/平台控制数据库Bootstrap.md)

## 背景

审计发现两个独立缺陷，都源于把「当前可用」与「曾经绑定」当作同一个信号。

**B — 就绪信号说谎。** `BindingStore.Snapshot()` 的 ready 就是 `s.store != nil`，一旦 `Bind()` 调用过就在进程生命周期内永远为真。`platformControlCoordinator.Allow()` 用它做 Full 层激活门禁（`platform_control_startup.go`），导致 Database Runtime 全实例消失后门禁仍持续放行——每个被放行的单元启动后第一次读 Shared State 即失败，累积 restart backoff，把一次本可无损推迟的依赖停机放大成全平台 Full 层激活失败风暴。

**C1 — 订阅关闭后引导协调器永久失去重试能力。** `coordinator.Run` 的旧实现在 `updates` channel 关闭时直接 `return`。`Controller.Start()` 的唯一调用者就是 `reconcile`，唯一触发者就是 `Run`；Node Agent 的定时轮询只调 `Allow()`，不碰 `Start()`。Router 重建一次之后，Open 永远不会被重试，平台永久停在未绑定状态，唯一出路是重启内核。同样地，如果 reconcile 失败且此后再无 topology 边沿到来，也会形成同样的永久搁浅。

## 决策

**B — 激活门禁使用活跃性信号而非历史绑定记录。**

`BindingStore` 增加独立的 `Live()` 方法，语义为「当前可用」。它由调用结果喂养：`ErrUnavailable` 清除（Provider 不可达），任何应用级错误（`ErrNotFound`/`ErrConflict`/`ErrInvalid`）保留（这些错误证明 Provider 已应答）。`Bind()` 设为 true（刚验证过连通性）。`Snapshot()` 的语义不变，仍为「曾经绑定」，供其他调用方（`controller.go` 的 phase 判定）继续使用。`Allow()` 改为调用 `Live()`。

这样做：Provider 消失时 `Live()` 在下一次调用失败后立即回落，门禁开始延后激活（`ErrActivationDeferred`，无损）；Provider 恢复后下一次成功调用自动恢复 `Live()`，无需重新 `Bind()`。

关键约束：`Live()` 在未绑定时返回 false，`required=true && store==nil` 仍映射到 `ErrUnavailable`。新增的活跃性路径不得成为 fail-open 的入口，不与 ADR-0197 的 fail-closed 保证相矛盾。

**C1 — 引导协调器带退避重新订阅，并在非稳态下定时重试。**

`Run` 重构为外层循环（带退避）驱动 `watch`；`watch` 持有一次订阅的生命周期并在 channel 关闭时 `return true`，外层循环据此重新订阅而非退出。`reconcile` 改为返回 bool（true = 已就绪），供 `watch` 决定是否需要武装重试计时器：失败时以有界指数退避（初始 500ms、上限 30s）重试；成功后退避重置、计时器不再触发（稳态零开销）。Context 取消立即停止所有循环。

文档「没有定时兜底轮询」的表述被替换为更准确的说明：稳态零轮询，但**非稳态**（已提交 Profile 但尚未绑定）下有有界退避重试。这与原设计意图（避免亚秒级无效扫描）不矛盾，因为退避从 500ms 起、只在确实失败时激活。

## 影响

- `BindingStore` 增加 `live bool` 字段与 `Live()` 方法、`observe(err)` 内部辅助。五个数据方法在委托调用之后各插入一次 `s.observe(err)`。`Snapshot()` 的签名与语义均不变，6 个非测试调用点无需修改。
- `platform_control_startup.go` 的 `Allow()` 改用 `c.binding.Live()`；同文件提取 `platformControlAdministration` 接口（嵌入 `platformcontrolport.Administration` + `Start`），使 C1 的重试循环可在不依赖真实 Database Runtime 的情况下测试。
- 新增 `binding_liveness_test.go`（4 个测试）与 `platform_control_retry_test.go`（2 个测试），均已反向验证：还原旧实现后如期失败。
- 更新 Bootstrap 设计文档第 85-86 行（startup_tier 与 topology change 段落）。
