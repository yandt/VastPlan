# ADR-0184 表单控件对齐与页面正文分段组件

## 状态

已接受，2026-08-01。

## 背景

业务表单已经统一使用 `FormPresentation`，但输入控件在字段区域内的水平对齐仍由具体页面或 Renderer 默认样式决定。外观设置页的“主题与颜色”“偏好设置”也直接使用 React 行内样式绘制标题、说明、间距和分隔线。继续复制这种做法会让新插件形成不同的正文节奏，并迫使每个 UI 框架重复修正页面样式。

## 决策

1. UI Contract 8.5.0 在 `FormPresentation` 增加 `controlAlignment: start | end`。省略时统一解析为 `end`；确有左对齐需求的表单必须显式声明 `start`。
2. `controlAlignment` 只决定控件在受治理字段区域中的水平位置，不改变字段列宽、控件尺寸、Label 布局或输入文本对齐。全宽控件仍占满可用区域，内在宽度控件贴近相应边缘。
3. SDK Helper、Workbench 准备阶段与 Renderer 只消费同一字段，不接收框架样式、像素宽度或环境分支。未知值在注册或准备阶段失败关闭。
4. `PortalUI` 增加 `BodySections` 语义组件。调用方只提供稳定 Section ID、标题、说明和内容；Renderer 统一拥有标题层级、16px 内部节奏、24px Section 间距和相邻区域之间的分隔线，最后一个区域不绘制多余分隔线。
5. 配置与管理页面的 Body 一级分区默认使用 `BodySections`，Workbench 独立 Page 表单同步迁移并移除 Panel 卡片外壳。功能插件不得自行复制标题、说明、底部边框和 Section 外间距；若 Workbench Pattern 还不能表达目标页面，应先扩展 Pattern 或公共组件面。
6. 外观设置页成为首个真实迁移对象：“主题与颜色”和“偏好设置”由一个 `BodySections` 实例渲染，主题模式保留在“主题与颜色”区域内。

## 结果

- 所有 Workbench 动态表单获得相同的默认控件对齐策略，并可通过受限语义显式调整。
- Body 级配置区域不再依赖页面私有 CSS；当前 Ant Design Renderer 和未来 Renderer 只需实现同一组件契约。
- 该决策不允许插件绕过 Workbench、传入任意样式或把业务 React 节点注入数据驱动页面定义；`BodySections` 是 Renderer 组件面，功能页面仍须遵守既有 Workbench 数据驱动规则。
