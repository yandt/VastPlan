# ADR-0153 Kernel Service 可信授权编译

- 状态：已采纳，已实施
- 日期：2026-07-26
- 关联：[ADR-0031](ADR-0031-Backend内核1.0封板与工程门禁.md)、[ADR-0048](ADR-0048-发布者级插件运行策略.md)、[ADR-0061](ADR-0061-统一调用信封与受众投影.md)、[ADR-0148](ADR-0148-公共服务基线与种子配置分域.md)、[ADR-0152](ADR-0152-插件边界门禁与权限策略物理收敛.md)

## 背景

插件 Manifest 的 `capabilities.kernelServices` 已经限制 HostCall，但此前可信宿主直接把清单申请编译为 Grant。签名能证明“谁发布了这份申请”，不能证明当前平台愿意授予它；第三方发布者只要通过制品准入，就可能把申请误当授权。与此同时，服务组合未显式保存授权结果，运维方也无法审计某个运行单元实际获得了哪些内核能力。

内核需要保持通用，不应内置具体插件 ID 白名单；dynamic-go、Go/Python/Node 进程及未来隔离 Runtime 也必须经过同一授权路径。

## 决策

### 1. 三层输入和宿主事实共同约束

Node Agent 为每个插件编译不可变 Kernel Service Grant：

`已验签 Manifest 申请 ∩ ServiceUnit 精确授权 ∩ 发布者策略上限 ∩ 候选宿主已注册服务`

- Manifest 只能申请，不能自行授权；
- `config.kernel_service_grants.<pluginId>` 保存 Platform Profile 或可信部署解析结果的精确服务名，不接受通配符；
- 内核运维方可以设置未知发布者默认上限和发布者精确覆盖。默认未知发布者为空，首方 `vastplan` 上限为全部已注册服务；
- 即使前三层允许，候选宿主没有注册具体服务时也拒绝启动。

发布者上限通过 `-default-plugin-kernel-services` 和 `-publisher-plugin-kernel-services` 配置。服务单元精确授权是授权决策记录，不是插件普通业务配置；在线管理必须通过可信部署解析和发布流程产生，不能由插件进程回写。

### 2. 当前申请全部按必需依赖处理

现有 Manifest 没有 required/optional 区分。因此只要插件申请 Kernel Service，服务单元必须完整授予申请集合。缺项会在进入任何执行驱动前拒绝候选，而不是启动一个已知残缺的插件；额外授权同样拒绝，避免配置漂移或越权意图被静默忽略。

未来若确有可降级需求，应先升级 Manifest 契约，明确拆分 required/optional，并由 Grant 编译器裁剪 optional；不得把“部分授权”作为当前格式的隐式语义。

### 3. 所有运行驱动共享 LaunchPolicy

Node Agent 只把编译后的精确结果写入可信 `LaunchPolicy`。进程插件在握手时编译会话 Grant，dynamic-go 在嵌入式调用边界使用同一 Plan；插件 wire 消息不能提供或扩大 Grant。实际态记录每个运行单元的精确 Grant 快照，供控制面诊断和审计。

## 备选方案

### 只信任签名 Manifest

实现最简单，但签名只表达来源真实性，不能替代平台授权，尤其不适合第三方插件，否决。

### 在内核硬编码插件 ID 白名单

短期直观，但把业务插件拓扑写进内核，新增插件都要求改内核并容易产生别名特例，否决。

### 缺失 Grant 时自动按 Manifest 补齐

能降低迁移成本，却会重新把申请变成授权，并掩盖服务配置遗漏，否决。当前开发阶段直接迁移种子和示例配置。

### 允许部分 Grant 后启动

缺少 optional 语义时会把确定性配置错误推迟成运行时故障，否决。

## 影响

- 第三方发布者默认不能调用任何 Kernel Service，必须由内核运维方显式设置发布者上限；
- 每个请求 Kernel Service 的服务单元必须包含精确 `kernel_service_grants`，旧配置不会静默兼容；
- 授权失败发生在候选启动之前，不会触发插件代码；
- Go、Python、Node、dynamic-go 和未来隔离 Runtime 不会形成不同权限模型；
- 实际态可直接展示精确 Grant，便于排查“清单申请、平台授权、发布者上限、宿主实现”中的哪一层拒绝；
- 当前配置仍是可信发布结果的载体；在线配置界面不得把该字段暴露为普通插件可编辑值。
