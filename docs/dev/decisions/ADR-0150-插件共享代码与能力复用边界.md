# ADR-0150 插件共享代码与能力复用边界

- 状态：已采纳，迁移中
- 日期：2026-07-25
- 关联：[ADR-0017 版本定义与兼容性机制](ADR-0017-版本定义与兼容性机制.md)、[ADR-0047 多语言运行驱动与第三方隔离边界](ADR-0047-多语言运行驱动与第三方隔离边界.md)、[ADR-0144 组合服务代际热升级与插件动态调试](ADR-0144-组合服务代际热升级与插件动态调试.md)、[ADR-0146 开发构建锁一致性与稳定制品身份账本](ADR-0146-开发构建锁一致性与稳定制品身份账本.md)

## 背景

当前 Go 插件和 Go SDK 大量直接导入 `core/shared/go`，部分基础插件还导入 `core/kernels/backend`。该目录同时承载公开 wire 类型、插件侧协议帮助器、可复用算法、可信宿主状态和内核基础设施实现。内核普通重构因此进入插件编译依赖闭包，使多个未修改业务源码的 stable 插件同时产生新字节并触发不可变制品身份保护。

完全禁止共享会复制安全校验和多语言协议；把全部共享能力放入普通 SDK 又会形成大包、扩大升级半径；把每段纯计算都改为插件调用则会增加延迟、启动依赖和故障面。

## 决策

1. 插件复用采用四种明确形态：
   - `contracts`：语言中立协议、Schema、生成类型、稳定标识和 wire 兼容规则；
   - `extensions/sdk/<language>`：插件侧生命周期、HostCall、配置、状态、凭证等协议客户端与安全默认值；
   - `extensions/libraries/<language>`：无宿主权限、无隐藏状态的可选纯算法库；
   - Provider/Service 插件：需要在线替换、独立配置、状态、凭证、集群或跨语言访问的运行能力。
2. 插件不得直接或传递依赖 `core/**`，不得导入其他插件实现。内核专用共享实现进入 `core/internal/**`，利用 Go `internal` 规则形成编译期边界。
3. 内核和 SDK 可以共同依赖 Contracts；内核不得依赖插件 SDK。SDK 只能依赖 Contracts、同语言公开 Library 和第三方依赖，不得依赖内核或具体插件。
4. 插件间不以插件 ID 或源码包复用能力，而以版本化 capability/protocol 由内核寻址。调用方不感知本地 Provider、共享 Runtime Host 或远端集群实例。
5. Contracts、SDK 与 Library 独立版本化。Go 构建把实际导入的 SDK/Library 静态编入插件；Node 可由可信 Runtime 外置明确允许的官方 SDK；Python Runtime 可提供基础 SDK，其他依赖使用锁定 wheel。所有形态都必须进入制品 SBOM 和兼容性验证。
6. 单插件构建摘要只包含插件源码、实际依赖的 Contracts/SDK/Library、语言锁文件、构建器和工具链。不得继续以整个 `core` 或全部插件目录作为每个插件的共同输入。
7. SDK 或 Library 字节变化导致已链接 Go 插件字节变化时，插件必须产生新 SemVer；内核内部变化不得导致插件重建。运行时提供的兼容 SDK 变化由 Runtime/SDK 约束和 Host Generation 管理。
8. dynamic-go 继续只允许策略批准的第一方插件，以精确 Host ABI 指纹和独立 Generation 运行；它不是通用共享库或第三方插件依赖机制。

## 备选方案

- 每个插件复制全部公共代码：隔离最强，但安全修复、协议行为和多语言实现必然漂移，否决。
- 全部复用都进入一个统一 SDK：短期迁移简单，但重新形成大包和全量重建，否决。
- 全部复用都改为运行时插件调用：可动态替换，但纯函数和高频小调用成本过高，并引入启动环和额外故障面，否决。
- Go 使用系统动态链接库共享依赖：ABI、卸载、跨平台和供应链边界不稳定，不作为普通插件机制。

## 影响

- 内核普通重构不再改变插件制品，stable 身份漂移只反映插件或公开依赖的真实发布变化。
- 可替换、有状态或高权限能力获得独立生命周期、配置、扩缩容和安全边界。
- Contracts/SDK 的兼容性成为正式发布对象，需要跨语言 golden、SBOM、版本策略和依赖图门禁。
- 现有 `core/shared/go` 需要按职责迁移，不能整体改名；迁移完成前以只减不增的依赖基线阻止新增违规。

当前目录、调用和构建规则以《[插件共享代码与能力复用](../architecture/插件共享代码与能力复用.md)》为单一真相源。

## 实施记录

- 2026-07-25：完成 Go 边界首轮迁移。Protobuf 生成物进入 `contracts/generated/go`；协议常量、错误码、资源限制、扩展点、只读上下文视图、Runtime Audience 和 dynamic-go ABI 进入 `contracts/runtime/go`；可信 CallContext 与 RuntimeIdentity 进入 `core/internal`。
- 2026-07-25：建立 `extensions/libraries/go`，迁入签名制品仓库、供应链、配置激活、Shared State 等可复用实现。普通插件与 Go SDK 对 `core/**` 的直接导入归零，架构测试改为永久 fail-closed 门禁。
- 2026-07-25：Platform Dev 的 Go 构建缓存改为按二进制真实 `go list -deps` 闭包计算。插件源码、实际 Contracts/SDK/Library、清单、锁和工具链分别形成摘要，不再把整个内核作为全部插件的共同构建输入。
