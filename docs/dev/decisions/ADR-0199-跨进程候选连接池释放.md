# ADR-0199 跨进程候选连接池释放

- 状态：已接受
- 日期：2026-08-08
- 关联：[ADR-0198 激活门禁活跃性与引导重试](ADR-0198-激活门禁活跃性与引导重试.md)、[ADR-0197 平台控制 Profile 存在性作为 Provider 必需的真相源](ADR-0197-平台控制Profile存在性作为必需真相源.md)、[平台控制数据库 Bootstrap](../architecture/平台控制数据库Bootstrap.md)

## 背景

设计文档要求「候选 Store 在 Profile 提交或绑定失败时必须关闭自身连接池」。P4c 把连接池移进独立 Database Runtime 进程后，这条不变量在实现上失效了，而文档未随进程边界拆分更新。

`RemoteStore.Close()` 是 `return nil`，注释自陈「Runtime generation lifecycle owns the physical pool」。宿主侧没有任何 RPC 通知副本释放，因此 `Controller` 里四处 `_ = store.Close()` 在生产远端路径下全是空操作。

`openReplicas` 的中途失败更彻底：循环里某个副本失败即 `return nil, err`，此前已成功 `Initialize`/`Open` 的副本既不进入 `b.replicas`，也不被任何返回的 Store 引用，此后没有任何代码路径能回收它们。

泄漏是有界且最终自愈的——Runtime 在 `activate()` 装入新池时会 `previous.Close()`，进程退出时 `Service.Close()` 也会释放。但运维排查故障时反复重试 Configure（改 host、改密码、改 schema），每次失败都在每个副本上留下一个陈旧池，逐步侵蚀按 `clusterMaxOpen × clusterMaxReplicas` 生成的每实例连接硬预算。

## 决策

**Bootstrap Capability 加法式新增 `close` 操作**，载荷是最小结构 `CloseRequest{Generation uint64}`。Capability 从 `3.0.0` 演进到 `3.1.0`：`3.0.0` 副本仍然有效，只是无法被告知释放候选池。

**宿主侧**：`RemoteStore` 记住自己代表的 generation，`Close()` 逐副本发出 `close`，5 秒超时且忽略错误——它运行在已经有错误要上报的失败路径上，不能阻塞它们，而已经消失的副本本就随进程释放了池。`openReplicas` 中途失败时对 `opened` 列表逐个补偿释放再返回错误；这一步不能交给 `RemoteStore.Close()`，因为那些副本从未进入任何被返回的 Store。

**副本侧**：`Service` 增加 `managedGeneration`，在 `activate()` 装入池时记录、在释放与 `Close()` 时清零。`closeHandler()` 独立于 `handler()`：释放既不需要解析 Profile 也不需要解析秘密，副本只是被告知丢弃自己已拥有的池。仅当 `managed != nil && managedGeneration == request.Generation` 才关闭。

## 理由

generation 判据是这个设计的关键。若无条件关闭 `s.managed`，一个迟到的释放就能关掉后续激活装入、正在服务 Shared State 的池，把资源清理机制变成可用性故障源。`execute()` 与 `closeHandler()` 共用同一把互斥锁，释放与激活互斥，判据在锁内求值可靠。

释放不携带秘密是有意的：副本已经持有该池的一切，请求只需指明释放哪一代。代价是 SYSTEM 调用者校验成为唯一屏障，因此 `closeHandler()` 保留与其他操作相同的 `trustedBootstrapCaller` 检查，并额外拒绝 `generation == 0`。

采用加法式演进而非原地修改契约，与 wire 契约的既有纪律一致。混代运行期间只是拿不到候选释放能力，退回既有的「等下一次激活替换」行为。

## 影响

- 契约新增 `OperationClose` 与 `CloseRequest`；`BootstrapContractVersion`、Database Runtime manifest 的 `contractVersion` 同步到 `3.1.0`，插件版本 `0.16.2 → 0.17.0`（manifest 与 `databaseruntime/provider.go:PluginVersion` 两处版本身份必须一致，有门禁 `TestArch_BackendPluginVersionMatchesManifest` 把守）。V1 兼容矩阵冻结 `3.0.0` 为下限，minor 抬升合规。
- `RemoteStore.Close()` 不再是空操作，`Controller` 里既有的 4 处调用自动获得真实语义，调用方无需改动。
- 新增 6 个测试：库侧覆盖中途失败补偿、完整释放、generation 记忆；副本侧覆盖幂等释放、陈旧 generation 静默无操作、非可信调用者与无效载荷拒绝。均已反向验证。
- 未涉及审计发现的 C6（bootstrap 层单元换版发布路径成环，需独立 ADR 定方向）与 C5（`remote.go` 把不可解析响应压成 `ErrUnavailable`，严重度低）。
