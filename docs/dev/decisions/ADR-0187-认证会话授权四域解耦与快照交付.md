# ADR-0187 认证、会话、授权管理与权限判定完全解耦

- 状态：已采纳，分阶段实施
- 日期：2026-08-02
- 关联：[ADR-0106](ADR-0106-多端统一身份授权与Runner执行租约.md)、[ADR-0107](ADR-0107-插件权限目录与系统管理授权治理.md)、[ADR-0108](ADR-0108-会话前Access-Profile与认证方法协议.md)、[ADR-0109](ADR-0109-种子访问与企业身份Provider分离.md)

## 背景

现有系统已经把登录 Provider、Authorization Policy、Authorization Session 与 Enforcer 拆成不同插件，但运行装配仍有三处不完整：Portal Session 由 Node 内置密封 Cookie 固定实现；Policy 的 `authorization.store.v1` Profile 已存在，Backend 却仍直接绑定 Shared State Adapter；Enforcer 声明 Native Engine Provider，热路径仍直接调用同包 Go 求值器。签名快照还通过共享文件交付，启动工具与 Policy 插件曾各自续签并覆盖同一文件，最终产生快照 revision、TTL 和 audience 漂移，导致认证成功后无法建立会话。

## 决策

系统固定分为四个业务域和一个窄交付域，任何实现都不得跨域拥有状态或权力：

1. **Authentication Method** 只证明主体身份，使用 `authentication.method.v1` 输出短时 Evidence/Assertion；不得签发平台权限或长期 Session。
2. **Identity Session/Token** 只消费已验证 Assertion，负责 Session、Access Token、Refresh Token、吊销、轮换和载体适配；存储实现通过独立 Provider Profile 选择，不保存角色定义。
3. **Authorization Policy Management** 只管理 Permission Catalog、Role、Binding、Domain、撤权和审计；权威状态只能经 `authorization.store.v1`，不得依赖 Portal Cookie 或认证 Provider 私有表。
4. **Authorization Decision** 只验证调用上下文并执行权限判定；求值实现通过 `authorization.engine.v1` 选择，Enforcer 不修改 Policy 状态。
5. **Signed Snapshot Distribution** 只发布、订阅、校验和原子切换签名 Policy Snapshot；它不解释角色、不决定 allow，也不持有登录会话。文件、NATS、对象存储或数据库只能是该端口的 Adapter。

四域之间只允许按以下稳定对象单向传递：

```text
Method Provider -> Signed Authentication Assertion
Assertion -> Session/Token Provider -> Authenticated Principal
Policy Store -> Policy Service -> Signed Policy Snapshot
Signed Policy Snapshot -> Distribution -> Enforcer/Authorization Session
Principal + Request + Snapshot -> Decision Engine -> Decision Proof
```

禁止共享数据库表、私有 Go/TypeScript 对象、物理文件路径或环境模式字符串。Provider 在组合根选择一次，后续层只依赖协议端口。代码不得判断 development/production；部署差异只能表现为 Profile、租约参数、受众和 Provider 选择。

## 快照租约

Authorization Policy 是签名快照租约的唯一权威。Bootstrap 只创建首次 Seed 输入，不在普通启动时续签运行态授权。Policy 作为受宿主约束的 `leader + external-shared` 后台控制器，采用两阶段激活：ACTIVATE 只注册控制器；宿主确认插件 Active 并授予后台身份与 Leader Fence 后，控制器立即完成：

1. 从权威 Store 加载状态；
2. 依据组合根注入的 `SnapshotLeasePolicy` 协调受管 Binding；
3. 续签到期或配置不一致的 Snapshot；
4. 修复本地 Projection 与权威 `CurrentSnapshot` 的漂移；
5. 成功后按精确到期边界设置下一次定时器。

控制器不得在 ACTIVATE 内提前伪造 Active 身份，也不得绕过 Leader Fence。首次协调完成前，Authorization Consumer 继续以现有签名快照和 LKG 规则 fail-closed；健康状态不做固定频率轮询。Shared State 暂时不可用时使用有界重试，现有未过期快照仍可工作，越过有效期后继续 fail-closed。

## 当前实施边界

- 已完成 `SnapshotLeasePolicy` 注入、Active/Fence 建立后的首次协调、精确到期定时续签、受管 Seed Binding 续签和本地 Projection 修复。
- 已删除 `platformdev` 普通启动直接续签 Policy 文件的第二权威路径。
- `authorization.store.v1`、`authorization.engine.v1` 的跨语言 DTO 已存在，但 Policy/Enforcer 的默认运行接线仍需从直连 Go Adapter 改为 Provider Port。
- `identity.session.v1` 与 `authorization.snapshot.v1` 的公共 wire contract、Provider Catalog 和多实现验收尚未完成；在完成前，密封 Cookie 与本地文件只能标记为默认 Adapter，不能宣称已经多协议化。

## 语言与运行方式

- Method Provider 按协议生态选择 Node.js、Go、Java、Python 等语言；第三方默认独立隔离。
- Session/Token Authority 与 Snapshot Controller 默认 Go，便于确定状态机、CAS、签名和低资源常驻；Portal Cookie Adapter 可使用 Node.js。
- Native Decision Engine 使用 Go；OPA/Cedar/Casbin 等 Provider 按其成熟生态选择 Go、Rust、Java 或其他语言，并通过稳定 RPC 契约接入。
- Provider 语言与进程形态独立决策，同语言第一方实现默认进入共享 Runtime，只有隔离策略要求时才单独进程。

## 影响

- 登录成功不再意味着已获得权限；Session 只引用稳定主体与授权投影 revision。
- 更换 Session Store、Policy Store、Decision Engine 或 Snapshot Transport 不需要修改登录 Provider 或业务插件。
- 任一 Provider 不可用时只影响其所属域，并按该域协议定义的 fail-closed/LKG 语义处理，禁止跨域降级到另一实现。
- 后续实现必须为首次执行、嵌套调用、热替换、恢复、吊销和多节点接管使用同一协议链编写测试。
