# ADR-0160 精确制品摘要贯穿与事件驱动依赖监督

- 状态：已采纳并实施
- 日期：2026-07-26
- 关联：[ADR-0098](ADR-0098-制品依赖解析锁与离线Bundle.md)、[ADR-0157](ADR-0157-开发Seed-Runtime-LKG快照.md)、[ADR-0158](ADR-0158-应用插件兼容范围与精确运行锁.md)

## 背景

系统已经把版本范围限制在显式规划阶段，并由 Artifact Lock 选择精确版本；但最终 Deployment/Assignment 仍只携带 `pluginId + version + channel`，SHA-256 只存在于 Artifact Lock 和仓库元数据。Controller 因而在每次节点或实际态事件、周期轮询时重复读取全部 Manifest，Node 也只能间接依赖“精确三元组在仓库中不可变”的全局约束。

运行依赖监督原先每 500ms 扫描 capability 目录并重新解析 SemVer。与此同时 Addressing Router 已有目录 watcher 和低频全量刷新；高频扫描既重复，又没有过滤已经超过 `lease_expires_at` 的陈旧记录。

## 决策

1. 版本范围只存在于 Application Intent、Manifest 和显式 Resolver 请求。Repository 只在规划/发布工作流中求解一次，输出精确 Artifact Lock。
2. Composition Planner 从 Artifact Lock 生成候选时携带包 SHA-256；Kernel Resolver 再从可信制品元数据复验，并把 `id + version + channel + sha256` 写入 Deployment v2。Scheduler 原样复制到 Assignment v1。Deployment 与 Assignment 的运行契约必须包含 64 位小写 SHA-256；未解析的 Platform Profile/Application Composition 输入可以暂不携带。
3. Controller 仍在新的 Deployment digest 上读取签名 Manifest，复验来源、身份、部署策略、包依赖、capability 版本和 DAG；成功结果按 Deployment digest 缓存。节点租约、ActualState 和周期调度事件复用该缓存，不再重复读取制品。失败结果不缓存，以便仓库恢复后重试。
4. Node Agent 按 Assignment 精确三元组获取制品，并要求验签结果的 SHA-256 与 Assignment 完全一致；安装器继续在落盘边界复算摘要。插件进程握手继续绑定实际运行 ID/版本、内核 engines 和 Host Protocol，不能由前置锁替代。
5. Addressing Router 是运行依赖拓扑的唯一观察者：远端目录 put/delete、全量刷新以及本地注册激活/更新/关闭均广播拓扑变化；查询必须排除过期租约。Runtime 只在拓扑事件或当前匹配租约的精确到期时间到达时重新判定依赖，SemVer constraint 只编译一次并缓存。
6. 只保留 Router 每 30 秒一次的全局目录反熵，用于修复 watcher 重连缺口或本地缓存漂移。Runtime 不再另设低频轮询；Router 反熵结果会通过同一拓扑事件广播。该兜底只重建目录快照，不执行版本求解、制品下载或插件重启。
7. 开发平台的 stable Seed 继续由 LKG 快照承载。显式 `bootstrap` 在 Profile 精确引用未变化时复用 stable LKG，并使用本次新物化的配置 Catalog；插件源码调试通过 `dev-plugin`/workspace Test Release。Profile 引用新 stable 版本时必须显式执行 `bootstrap --rebuild-seed`，才会重建 Seed 并进入 stable 身份账本；普通 `bootstrap` 不隐式生产 stable 制品。

## 影响

- 运行节点直接消费与 Artifact Lock 一致的内容摘要，仓库 tag 不可变不再是唯一保护层。
- Controller 的制品读取次数从“每次调度事件”降为“每个 Deployment digest 一次”。
- 强依赖在目录变化或租约到期时即时收敛，不再每 500ms 扫描；过期租约会被正确拒绝。
- 普通启动和仅配置重发不会因工作区源码变化重建 stable Seed；稳定版本提升只发生在明确的 stable 晋级动作。
- Deployment/Assignment 契约新增 SHA-256。项目仍处开发阶段，不保留缺少摘要的旧运行快照兼容分支。
- 已保存旧 DesiredState/Deployment 的开发环境需要显式执行一次 `bootstrap --rebuild-seed --fresh`；生产迁移方案在正式制品库与持久控制面定稿时另行设计，不能静默清空。

## 否决方案

- **Node 启动时按范围重新求解**：会造成重启漂移并破坏审批、回滚和离线恢复，否决。
- **删除 Controller/Node/握手中的全部重复检查**：这些检查位于不同信任边界，否决；改为摘要贯穿和按 digest 缓存。
- **Controller 每次 poll 重新读取所有 Manifest**：不能增加新的安全保证，且把健康事件放大为仓库负载，否决。
- **Runtime 自己再保留一套低频轮询**：Router 已提供 watcher、租约和全局反熵，第二套轮询只会重复，否决。
