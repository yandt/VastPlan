# ADR-0161 产品插件所有权与开发示例物理隔离

- 状态：已采纳，已实施
- 日期：2026-07-27
- 关联：[ADR-0060](ADR-0060-五大区域仓库布局与根目录收敛.md)、[ADR-0097](ADR-0097-测试制品仓库与前端分级热升级.md)、[ADR-0150](ADR-0150-插件共享代码与能力复用边界.md)、[ADR-0151](ADR-0151-最小Seed装配与开发插件候选分流.md)、[ADR-0152](ADR-0152-插件边界门禁与权限策略物理收敛.md)

## 背景

规则审计发现三种归属漂移：演示插件仍位于产品插件目录并被旧命名空间白名单放行；Workbench Gallery 为进入真实 Portal 使用了 `product` 身份；Artifact Assessment 的具体 Trivy Provider、扫描工作流和签名实现位于 SDK。与此同时，Frontend Runtime 虽已由组合根选择开发/生产协议，下层 API 仍能省略协议并自行回退默认实现。

这些做法不会立即导致测试失败，却会让产品制品、开发样例、SDK 和插件所有权重新混合，并允许后续调用链绕过统一协议。

## 决策

1. `extensions/plugins` 只保存可发布的 Product/Foundation/Platform/Integration 插件；`examples/plugins` 保存可打包、可热调试但永不进入生产默认组合的示例插件。
2. 示例统一使用 `cn.vastplan.example.<category>.<component>`，由 `ManagementDevelopment` 分类；产品目录出现 Development 插件、示例目录出现非 Development 插件均由架构测试拒绝。
3. Backend 与 Frontend 开发工具可以显式发现 `examples/plugins`。生产构建默认只扫描产品目录；Portal 只有在 Backend 组合根选中开发策略时才接受 example 制品。
4. 示例 Backend 配置迁入 `examples/deploy`。`engineering/deploy` 只保留平台管理 Seed、公共基线和正式配置模板。
5. Artifact Assessment 的 Provider、Trivy 进程、解包、策略归一化和私钥签名实现归回其插件。SDK 不再拥有具体 Provider；跨数据库快照插件共享的部分收敛为只消费 `io.Reader` 的确定性 Trivy revision Library，文件权限和生命周期仍由各插件自己负责。
6. Frontend Runtime 协议只在 Portal 组合根选择。Generation、Fetcher 和 Parser 的下层 API 必须显式接收同一协议对象，不提供开发/生产默认值或平行快捷入口。
7. 每个产品和示例插件必须拥有本地 README；`docs/dev/plugins` 只保存需要跨文件阐述的深度设计，不再维护第二份完整插件清单。

## 语言与运行方式

Assessment Provider 继续使用 Go 可信编排壳和外部 Trivy。Go 对受控子进程、文件权限、短期私钥和现有 Material Lease 契约最合适；Python 适合未来 ScanCode Provider，Node.js 没有本场景生态优势，Rust 可用于未来更小可信壳但当前迁移成本过高。本次只改变代码所有权，不新增进程或改变独立 `trusted-process` 运行方式。

示例保持各自验证目标所需语言：Go 用于 Backend 分发样例，Python 用于异构 Runtime 样例，TypeScript 用于 Workbench 样例。运行方式与语言分别由示例 Manifest 声明。

## 影响

- 生产插件目录、Seed 和默认 Portal 不再混入演示身份。
- 开发样例仍能通过 testing/workspace 制品、Frontend HMR 和 Test Release 使用真实运行链。
- 第三方 Provider 只依赖公开契约、Library 与 SDK 客户端，不会链接第一方 Trivy 实现。
- 新调用路径无法因省略参数而悄悄恢复另一套 Runtime 校验语义。
- 新增顶层 `examples/`，只承载可运行示例及其配置，不承载生产状态或业务实现。
