# ADR-0194 平台控制数据库与声明式数据分层

- 状态：已采纳
- 日期：2026-08-05
- 关联：[ADR-0095](ADR-0095-Database-Runtime多Provider连接池与集群事务.md)、[ADR-0109](ADR-0109-种子访问与企业身份Provider分离.md)、[ADR-0133](ADR-0133-Credentials保持Leader与Active-Active前置条件.md)、[ADR-0193](ADR-0193-第一方插件边界与Capability契约版本.md)

## 背景

开发态仍有插件把运行状态直接写入本机 JSON 文件。现有 `state.shared.v1` 已统一身份派生、CAS 和错误语义，但生产默认 Provider 是 NATS KV，SQL Provider 尚未实现。与此同时，Database Runtime 只有参数化 SQL 和事务契约，插件仍需重复编写数据类型、Repository 和迁移代码。

## 决策

1. 种子服务采用两阶段启动。Bootstrap 阶段只启动 Seed Access、最小认证授权链、静态 Portal 必需模块和 Database Runtime；SQL Shared State 就绪后才启动依赖平台状态的完整组合。
2. Database Runtime 内部增加 SQL Shared State、Record Store 和 Schema Controller 模块，不建立新的运行插件。Backend Kernel 只保留可绑定的 Shared State Store SPI 和分阶段启动机制。
3. 平台控制数据库使用保留的 `PlatformControlStoreProfile`。非敏感配置保存在受保护的本机 Bootstrap Profile；Linux 生产秘密使用 systemd credential，开发允许 0600 文件。Seed verifier、恢复根和控制库自身解密根不得写入控制数据库。
4. SQL 是种子生产默认 Shared State Provider；NATS KV 保持可选协议；File 仅用于单测、未初始化开发环境和明确的 Seed/Recovery 根状态。Provider 不可用时 fail-closed，禁止回退文件形成双真相源。
5. PostgreSQL 和 MySQL 同批支持。平台控制数据使用独立逻辑数据库或独立 schema；普通插件必须通过 Connection Manager 获得业务 `connectionRef`，不能选择保留控制库连接。
6. 数据能力严格分为 `DataModel -> Repository -> Application Workflow`。DataModel 不声明页面、权限和业务动作；Repository 不含业务规则；所有对外操作即使只有简单 CRUD 也必须经过显式 Workflow。
7. `data.model.v1` 是语言中立签名契约。Go 工具在构建期验证模型并为插件实际语言生成 Go、TypeScript 或 Python 强类型 Repository 源码；生成物按模型分文件提交，CI 复生成检查漂移。
8. 安全增量 Schema 变化可自动执行；删除、改类型、收窄约束和数据重写必须使用签名迁移、备份前置检查、单一 Schema Controller 和持久迁移账本。
9. 数据库访问逻辑集中于统一 Database Runtime 契约，物理上 active-active 多副本运行。各实例维护本地池，普通调用本地优先并允许远端故障转移；事务保持实例亲和；Schema 迁移单写。

## 影响

- 种子运行状态可以由企业数据库备份、复制和恢复；
- 普通服务不持有数据库驱动、密码或独立连接池；
- 插件只需声明数据模型即可获得类型安全的数据读写层，但不能绕过业务流程；
- 当前开发状态不迁移，允许清理后重新初始化；未来生产迁移必须另走签名迁移和恢复流程。
