# ADR-0203：受治理默认 UI Provider 替换

- 状态：已采纳
- 日期：2026-08-08
- 关联：[ADR-0178](ADR-0178-插件专属扩展点与可信扩展图.md)、[ADR-0202](ADR-0202-服务可选导航编排与展示文件夹.md)

## 背景

功能插件通常需要提供一个开箱即用的管理界面，但企业、行业或后续产品版本可能需要用向导、可视化编辑器或更高密度工作台替换默认界面。把 UI 与后端状态机一起复制会产生权限、发布和兼容分叉；允许插件传递 React 组件或修改 Shell 又会绕过 Workbench 和可信扩展图。

## 决策

### 1. 功能协议唯一，UI Provider 可替换

功能所有者继续唯一拥有 Backend Capability、管理 API、权限、状态和发布协议。默认 UI 与替换 UI 都只能调用同一公开管理协议，不得拥有第二套状态或写入旁路。

### 2. 复用插件专属扩展图

需要可替换默认 UI 的功能插件声明一个 `surface: frontend`、`kind: frontend.page`、`dispatch: single` 的扩展点，并以闭合 descriptor 固定允许替换的页面 ID 和导航目标。

- 没有贡献时，所有者注册内置默认 Workbench 页面；
- 存在一个贡献时，所有者不注册默认页面，贡献者从自己的签名模块注册替换页面；
- 多于一个贡献在可信候选装配阶段失败；
- 替换插件必须依赖所有者并声明兼容的扩展契约范围；
- 卸载替换插件后，下一代 Generation 自动恢复所有者默认页面。

默认回退和替换选择由同代不可变 `ExtensionGraph` 决定，不读取浏览器本地配置，也不在页面注册后竞争覆盖。

### 3. UI 仍受 Workbench 和页面所有权约束

默认 UI 与替换 UI 都通过 `addCollectionPage`、`addWorkspacePage`、`addFormPage` 或 `addRecordPage` 注册数据驱动定义。descriptor 只携带 JSON 身份和目标，不携带组件、函数、DOM、样式或任意回调。

`frontend.page` 的反向校验继续要求：注册页面属于贡献插件、页面 ID 与 descriptor 一致、导航目标属于扩展点所有者允许的 targets。替换 UI 不继承所有者权限；调用管理 API 时仍以当前用户、当前 Portal 和当前服务的真实授权执行。

### 4. 每项功能拥有自己的扩展点

内核不提供一个可替换任意页面的全局 UI 注册表。每个功能所有者只为自身公开稳定、版本化的 UI Provider 扩展点，以便独立提升契约、收窄目标和撤销不安全版本。

导航编排插件是首个使用者：它内置默认 Workbench 管理页，同时公开单一页面 Provider 扩展点。替换插件可以提供拖拽、批量规则或领域化导航设计器，但必须提交相同导航编排草稿并走相同发布流程。

## 结果

- 新功能可以先交付可靠默认 UI，再由独立插件增强体验。
- UI 替换随插件安装 Saga 和 Portal Generation 原子切换、回滚。
- 后端协议、权限和审计保持单一，不因 UI 多样化而分叉。
- Shell、Renderer 和 Workbench 不开放任意组件注入。
