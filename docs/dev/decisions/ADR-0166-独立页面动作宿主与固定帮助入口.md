# ADR-0166 独立页面动作宿主与固定帮助入口

- 状态：已采纳并实施
- 日期：2026-07-28
- 关联：[ADR-0074](ADR-0074-Portal组合Slot与纯布局插件分层.md)、[ADR-0111](ADR-0111-语义图标与Workbench页面动作宿主.md)、[ADR-0163](ADR-0163-Workbench动作数据契约与图标化操作面.md)

## 背景

早期页面动作复用了 Collection `ActionSpec` 的 `page.primary/page.secondary` placement，并由 Workbench 页面动作控制器桥接当前选择、条件可见性和执行入口。虽然最终仍挂入 `page.header.end`，但 Header 操作的生命周期暗中依赖 Collection/Record 实例，页面级“新建”与记录级“审批、退役”也容易混在一起。

Page Header 是页面级语义区，不应由表格选择、分页、行状态或具体组合组件控制。它还需要在所有页面最右侧保留统一帮助入口，并允许有限的文字呈现与溢出策略，而不能重新开放任意 React 组件。

## 决策

1. UI Contract 升级为 `6.0.0`。从 `ActionSpec` 删除 `page.primary/page.secondary`，新增独立 `PageActionSpec`；旧 5.x 定义不冒充 6.x 兼容。
2. `CollectionPageDefinition`、`FormPageDefinition` 和三类 Record Page 通过顶层 `pageActions` 与 `runPageAction(context, signal)` 声明页面命令。`PageActionContext` 不提供 selected row、Collection 查询或组件实例，只提供动作与页面刷新信号。
3. 依赖具体记录或记录状态的编辑、审批、发布、退役、差异和审计操作必须使用 `record.row` / `record.detail`。不依赖记录的新增、导入、全局发布和页面刷新才允许成为 Page Action。
4. Portal Kernel 为每页创建独立刷新控制器，将 Page Action Host 编译为 `page.header.end` 的受治理贡献；Collection/Record 只订阅刷新信号，不再向 Header 注册回调。Host 始终右对齐。
5. Page Action 默认使用纯语义图标 + Tooltip。只允许 `icon`、`icon-label`、`label` 三种显示档位，以及 `auto`、`always`、`never` 三种溢出档位；定义不能携带组件、HTML、SVG、render function 或选择条件。
6. Portal Kernel 为每个页面追加宿主所有的 `system.page.help`，排序固定为 `1_000_000`，因此始终位于最右侧。当前按钮提供统一“帮助尚未配置”反馈，未来可连接页面帮助目录；功能插件不能占用、替换或调整它的位置。
7. 页面动作最多直接显示四个，其他命令进入统一更多菜单。表单与 Overlay 仍只能引用页面已登记的受治理 ID；Page Action 表单收到空 selection，禁止借页面动作访问隐式记录。

## 备选方案

- 保留旧页面动作控制器并只修正 CSS 右对齐：视觉上可用，但状态边界仍错误，拒绝。
- 让 Shell 直接接收业务按钮组件：灵活但恢复任意 UI 注入，破坏多 Renderer、安全检查与数据驱动页面，拒绝。
- 将帮助按钮作为每个功能插件的约定动作：会遗漏、重复且无法保证最右位置，拒绝。

## 影响

- 功能插件需要一次性迁移：记录相关动作下沉到行/详情，真正页面命令提升到 `pageActions`。
- Page Header 操作可独立于 Collection、Form 和 Record Pattern 演进，Shell 继续只消费统一 Slot，不理解业务动作。
- UI 契约版本、Platform Catalog、Foundation 清单和生成注册表必须在同一变更中同步，避免运行期出现 `UI_CONTRACT_INCOMPATIBLE`。
